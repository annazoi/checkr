CHECKR - HOW TO GET EACH ENV VARIABLE
========================================
Fill the values into .env.local (already created, gitignored).
Already done for you: DATABASE_URL, NEXTAUTH_SECRET, NEXTAUTH_URL.


1) REDIS_URL + REDIS_TOKEN  (Upstash Redis - free tier)
--------------------------------------------------------
1. Go to https://console.upstash.com and sign up / log in.
2. Click "Create Database".
3. Name it (e.g. "checkr"), pick a region close to where Vercel will run
   your app (e.g. us-east-1 if you're not sure), type = Regional, click Create.
4. Open the database, go to the "REST API" tab.
5. Copy the value called "UPSTASH_REDIS_REST_URL" -> paste into REDIS_URL
6. Copy the value called "UPSTASH_REDIS_REST_TOKEN" -> paste into REDIS_TOKEN


2) SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASSWORD / SMTP_FROM  (any SMTP provider)
--------------------------------------------------------------------------------------
Use whichever SMTP-capable mailbox or provider you already have (Gmail app
password, Mailtrap for local testing, your hosting provider's SMTP, etc).
1. Get the SMTP host, port, username and password from that provider.
2. Fill them into SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD.
3. Set SMTP_SECURE=true if the provider requires TLS on connect (usually
   port 465); leave it false for STARTTLS (usually port 587).
4. Set SMTP_FROM to the "From" address/name emails should be sent as, e.g.
     Checkr <noreply@yourdomain.com>


3) BLOB_READ_WRITE_TOKEN  (Vercel Blob - free tier)
------------------------------------------------------
Vercel Blob stores evidence screenshots. Since you're deploying on Vercel
anyway, this lives in the same dashboard as your project.
1. Go to https://vercel.com/dashboard and open your project (or create it
   first by importing this repo, if you haven't deployed yet).
2. Top tabs -> "Storage" -> "Create Database" -> choose "Blob".
3. Name it (e.g. "checkr-evidence"), click Create.
4. Click "Connect Project" and select this project -> this automatically
   adds BLOB_READ_WRITE_TOKEN to your Vercel project's env vars for you.
5. For LOCAL dev, you still need the same value in .env.local:
   - Go to the Blob store's "Settings" -> ".env.local" tab, or
   - Run `vercel env pull .env.local` from the project root if you have
     the Vercel CLI installed and linked (`npx vercel link` first).
   Copy the BLOB_READ_WRITE_TOKEN value (starts with "vercel_blob_rw_")
   into .env.local yourself if you don't use the CLI.


4) RAWG_API_KEY  (RAWG.io - free tier, covers every platform, not just Steam)
----------------------------------------------------------------------------
1. Go to https://rawg.io/apidocs
2. Click "GET API KEY" (or "Sign up" if asked first - email + password,
   no credit card).
3. After signing up you're shown your API key immediately (also always
   visible later at https://rawg.io/login -> your profile -> "API").
4. Copy that key -> paste into RAWG_API_KEY
   Free tier: 20,000 requests/month, no expiry.


5) DISCORD_CLIENT_ID + DISCORD_CLIENT_SECRET  (Discord Developer Portal - free)
----------------------------------------------------------------------------
Lets people log in / sign up with "Continue with Discord" instead of email.
1. Go to https://discord.com/developers/applications and log in with a
   Discord account (create one for free if you don't have one).
2. Click "New Application", name it (e.g. "Checkr"), click Create.
3. Left sidebar -> "OAuth2" -> "General".
4. Copy "CLIENT ID" -> paste into DISCORD_CLIENT_ID
5. Click "Reset Secret" (first time only) to reveal it, copy it -> paste
   into DISCORD_CLIENT_SECRET (shown once - if lost, reset it again).
6. Still on the OAuth2 page -> "Redirects" -> click "Add Redirect" and add:
     http://localhost:3000/api/auth/callback/discord
   Click "Save Changes" at the bottom.
7. When you deploy on Vercel, come back and add a second redirect for your
   real domain, e.g.:
     https://your-app.vercel.app/api/auth/callback/discord


AFTER FILLING ALL VALUES IN
----------------------------
Run these from the project root:

  npm run dev
      -> starts the app locally at http://localhost:3000

  npm run sync-games
      -> pulls ~10,000 games (all platforms) from RAWG into your Postgres
         database (needs RAWG_API_KEY filled in). Safe to re-run any time --
         it updates existing games instead of duplicating them.

Already done (do NOT repeat unless you reset the database):
  npm run db:generate
  npm run db:migrate
  (plus the one-time moderation_actions immutability trigger, already applied)
